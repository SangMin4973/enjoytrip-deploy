# 맛집기행 알고리즘 적용 기획서

## 적용 목표

현재 Google Places API로 조회하는 음식점의 평균 별점(`rating`)과 평가 개수(`userRatingCount`)를 활용해 **별점순 정렬**과 **보정 추천순 정렬**을 추가한다. 기존 검색 결과를 입력으로 사용하므로 알고리즘 적용을 위한 외부 API 추가 호출은 필요하지 않다.

적용 범위는 현재 검색 페이지의 음식점 최대 15곳이다. 사용자는 정렬 방식을 선택해 같은 음식점을 서로 다른 기준으로 비교할 수 있다.

## 알고리즘 적용 기획서 #1

### 내용

안정 병합 정렬을 이용한 별점·평가 개수 기반 맛집 정렬 서비스.

### 적용 알고리즘

병합 정렬(Merge Sort)과 복합 비교자.

### 알고리즘 개요

음식점 목록을 절반씩 나누어 정렬한 뒤 두 목록을 병합한다. 별점이 높은 음식점을 우선하고, 별점이 같으면 평가 개수가 많은 음식점을 먼저 배치한다. 두 조건이 모두 같으면 기존 검색 순서를 유지한다.

- 자료구조: 음식점 배열과 병합용 보조 배열
- 시간 복잡도: O(n log n)
- 공간 복잡도: O(n)

### 적용 서비스

맛집 검색 결과의 기본 정렬인 **별점순**.

### 적용 서비스 개발 개요

Google 검색 응답에서 현재 페이지의 음식점 목록을 가져오고, 각 음식점의 별점·평가 개수·최초 검색 순서를 정렬 입력으로 사용한다. 병합 정렬은 직접 구현하며 비교 기준은 ① 별점 내림차순, ② 평가 개수 내림차순, ③ 최초 검색 순서로 정한다. 평가 정보가 없는 음식점은 목록 아래에 기존 순서대로 표시한다.

정렬 함수는 화면 처리와 분리하고 원본 배열을 변경하지 않는다. 정렬된 결과를 기존 음식점 목록에 적용하며, 선택된 음식점과 북마크는 장소 ID를 기준으로 유지한다. 화면에는 현재 페이지의 검색 결과를 기준으로 정렬했다는 안내를 표시한다.

### 적용 예시

| 음식점 | 평균 별점 | 평가 개수 | 정렬 순위 |
| --- | --- | --- | --- |
| A | 4.8 | 30 | 3 |
| B | 4.8 | 300 | 2 |
| C | 4.9 | 2 | 1 |

## 알고리즘 적용 기획서 #2

### 내용

베이지안 가중 평균을 이용한 평가 개수 기반 맛집 추천 서비스.

### 적용 알고리즘

베이지안 가중 평균 방식의 보정 점수 계산. 계산한 점수는 #1의 병합 정렬로 정렬한다.

### 알고리즘 개요

평가가 적은 음식점의 높은 별점이 과도하게 순위에 반영되는 문제를 완화한다. 평가 개수가 적으면 기준 평균의 영향을 크게 받고, 평가 개수가 많으면 해당 음식점의 평균 별점에 가까운 점수를 얻는다.

```text
보정 점수 = (v × R + m × C) / (v + m)

R: 음식점 평균 별점
v: 음식점 평가 개수
C: 기준 평균 4.0
m: 보정 가중치 50
```

C와 m은 초기 설정값이며 검증 결과에 따라 조정할 수 있다. 보정 점수는 비교를 위한 서비스 자체 지표로, 실제 음식의 맛이나 평가의 진실성을 보장하지 않는다.

- 자료구조: 음식점별 보정 점수 배열
- 점수 계산 시간 복잡도: O(n)
- 정렬 포함 시간 복잡도: O(n log n)
- 정렬 포함 공간 복잡도: O(n)

### 적용 서비스

맛집 검색 결과에서 선택할 수 있는 **보정 추천순**.

### 적용 서비스 개발 개요

현재 검색 결과 중 별점이 1~5점이고 평가 개수가 양의 정수인 음식점에 보정 점수를 계산한다. 보정 점수 내림차순으로 정렬하고, 점수가 같으면 원본 별점·평가 개수·최초 검색 순서로 비교한다. 평가 정보가 없거나 유효하지 않은 음식점은 점수를 계산하지 않고 목록 아래에 표시한다.

목록에 정렬 선택 기능을 추가해 기본 별점순과 보정 추천순을 전환하도록 한다. 평균 별점·평가 개수와 보정 점수를 구분해 표시하고, 추천 기준을 간단히 설명한다. 계산에는 반올림 전 점수를 사용하고 화면에는 소수 둘째 자리까지 표시한다. 점수는 현재 화면에서만 사용하며 북마크나 게시글에 저장하지 않는다.

### 적용 예시

아래 값은 알고리즘 확인을 위한 가상 데이터다. C=4.0, m=50을 적용한다.

| 음식점 | 평균 별점 | 평가 개수 | 보정 점수 | 추천 순위 |
| --- | --- | --- | --- | --- |
| A | 5.0 | 1 | 4.02 | 3 |
| B | 4.7 | 500 | 4.64 | 1 |
| C | 4.5 | 100 | 4.33 | 2 |

별점순에서는 A가 먼저 나오지만, 보정 추천순에서는 평가 개수가 충분한 B가 먼저 나온다.

## 구현 및 완료 기준

| 구현 항목 | 완료 기준 |
| --- | --- |
| 웹 알고리즘 | 별도 모듈에 병합 정렬과 보정 점수 계산 구현 |
| 화면 반영 | 현재 페이지에서 별점순·보정 추천순 전환, 선택 음식점·북마크 유지 |
| Java 제출 | 동일 알고리즘을 독립 실행 가능한 Java 코드로 구현 |
| 정확성 검증 | 동점·평가 없음·빈 목록·잘못된 값 검사, 웹과 Java의 동일 입력에 대한 결과 ID 순서 일치 및 점수 오차 1e-9 이하 |
| 성능 검증 | 합성 데이터 15·1,000·10,000개로 실행 시간 측정, 입력 생성·API 대기 시간은 제외 |
| 기존 기능 확인 | 검색·페이지 이동·상세·북마크 관련 기존 테스트 통과 |

웹은 `js/restaurant-ranking.js`에 두 알고리즘을 구현하고 `js/restaurant-app.js`의 목록 표시와 연결한다. Java 코드는 `algorithm-java/`에 소스·실행 방법·검증 데이터를 제공한다. Java를 웹 서버에서 호출하는 구조는 추가하지 않는다.

이번 구현 목표는 두 알고리즘의 검색 결과 적용과 Java 검증까지다. 전체 페이지 통합 순위, 거리순 정렬, 방문 동선 생성은 포함하지 않는다. 기존에 합의한 지도 연계의 공개 운영 검토는 알고리즘 구현 범위와 별도로 유지한다.
