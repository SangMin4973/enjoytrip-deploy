# 맛집 여행 프로젝트 기획

## 한 줄 소개

유저가 자연어로 여행 컨셉을 말하면 관련 맛집을 추천하고, 영상과 여러 리뷰를 직접 살펴본 뒤 원하는 음식점을 골라 여행 루트를 저장하는 서비스다.

## 목표

맛집 목록만 보여주는 데서 끝내지 않는다. 유저가 **왜 이 맛집이 내 여행에 맞는지**, **방문 전에 무엇을 확인해야 하는지** 판단할 수 있도록 인사이트를 함께 제공한다.

## 유저 흐름

1. **여행 컨셉 입력**: “부산에서 친구랑 로컬 음식 먹고 바다 보면서 쉬고 싶어”처럼 자연어로 입력한다.
2. **맛집 추천**: 지역, 음식 취향, 동행, 분위기, 예산 등 입력에서 확인할 수 있는 조건으로 후보를 찾는다.
3. **인사이트 확인**: 추천 이유와 함께 해당 맛집을 다룬 유튜브 영상, 카카오맵 리뷰, 블로그, 구글 검색 등을 살펴본다.
4. **음식점 선택**: 마음에 드는 음식점을 여행 목록에 담는다.
5. **여행 루트 생성**: 선택한 음식점의 위치를 기준으로 방문 순서를 구성한다. 유저가 순서를 바꿀 수 있어야 한다.
6. **저장과 재조회**: 여행 이름과 선택한 음식점, 방문 순서를 저장하고 다시 확인한다.

## 화면별 역할

| 화면 | 유저가 하는 일 | 보여줄 정보 |
| --- | --- | --- |
| 여행 컨셉 입력 | 자연어로 원하는 여행 설명 | 입력 예시, 해석된 조건 |
| 추천 목록 | 맛집 후보 비교 | 음식점 이름, 위치, 추천 이유, 확인 가능한 정보 |
| 맛집 상세 | 방문 여부 판단 | 가로로 펼친 영상 목록, 리뷰·블로그·구글 링크, 출처 |
| 여행 계획 | 음식점 선택과 순서 변경 | 선택 목록, 지도, 방문 순서 |
| 저장한 여행 | 계획 다시 열기 | 여행 이름, 선택 음식점, 저장한 순서 |

## 추천 데이터에 대한 제안

### 카카오맵 리뷰를 바로 추천 기준으로 쓸 수 있을까?

카카오 Local 장소 검색 API는 장소명, 주소, 좌표, 카테고리, 전화번호, 장소 상세 링크 등을 제공한다. 공개 응답에는 별점과 리뷰 본문이 없으므로, 이 API만으로 “카카오맵 리뷰 기반 추천”을 구현했다고 표현하면 안 된다. 리뷰는 우선 카카오맵 장소 페이지로 연결해 유저가 직접 확인하도록 한다. [카카오 Local 공식 문서](https://developers.kakao.com/docs/ko/local/dev-guide)

### 1일 프로젝트에 맞는 구성

- **후보 확보**: 한국관광공사 음식점 데이터 또는 카카오 장소 검색을 사용한다.
- **추천**: 자연어에서 추출한 조건과 확보한 음식점 정보가 일치하는 이유를 보여준다. 모르는 가격·분위기·대기시간을 추측하지 않는다.
- **영상**: 음식점 이름과 지역을 함께 검색한다. YouTube Data API의 `search.list`로 임베드 가능한 영상 후보를 가져올 수 있다. 검색 결과만으로 유튜버의 실제 방문을 확정하지 않고, 영상 제목·설명·지역을 확인한다. [YouTube 공식 문서](https://developers.google.com/youtube/v3/docs/search/list)
- **기타 리뷰**: 초기에는 블로그·구글·지도 검색 링크를 제공한다. 리뷰 수집과 요약은 이용 가능한 데이터와 제공 조건을 확인한 뒤 확장한다.
- **루트**: 초기에는 선택 순서 편집과 위치 기반 방문 순서 제안을 우선한다. 직선거리 정렬을 실제 도로 최단경로나 소요시간으로 표시하지 않는다.

AI를 붙이는 경우에도 실제 데이터에서 확보한 후보 안에서 추천하게 하고, 없는 음식점이나 리뷰를 만들어내지 않도록 제한한다.

## 이번 기본 코드와의 관계

이 문서는 **앞으로 만들 프로젝트의 기획**이다. 현재 코드는 사용자의 후속 요청에 따라 EnjoyTrip 명세서의 필수 기능만 구현한다.

| 구분 | 범위 |
| --- | --- |
| 지금 구현 | 지역·유형별 관광정보 조회, 회원가입·조회·수정·탈퇴, 로그인·로그아웃·비밀번호 재설정 데모 |
| 기획만 정리 | 자연어 맛집 추천, 영상·리뷰 인사이트, 음식점 선택, 여행 루트 생성·저장 |
| 나중에 결정 | AI 제공자, 추천 점수, 리뷰 수집 방식, 길찾기 API, 실제 회원 인증과 DB |

디자인은 이후에 진행한다. 기본 코드는 기능 확인이 가능한 단순한 폼과 목록으로 구성한다.

## 1일 작업 순서 제안

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 필수 기능 확인 및 API 키 준비 | 관광정보 조회와 회원 기능이 동작한다 |
| 2 | 컨셉 입력과 맛집 후보 연결 | 입력 → 후보 목록 흐름이 이어진다 |
| 3 | 영상과 외부 리뷰 연결 | 후보마다 실제 출처를 열 수 있다 |
| 4 | 음식점 선택과 루트 저장 | 선택 → 순서 편집 → 저장 → 재조회가 된다 |
| 5 | 오류 처리·화면 확인·발표 준비 | 데이터 출처와 미구현 범위를 설명할 수 있다 |

영상 API나 AI 연결이 늦어지면 검색 링크와 규칙 기반 조건 추출로 흐름을 먼저 완성한다. 이는 추후 확장 제안이며 현재 코드의 구현 범위는 아니다.
